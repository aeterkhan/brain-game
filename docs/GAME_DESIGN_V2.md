# 백지의 방 — 게임화 강화 기획서 (v2)

> 작성일: 2026-07-01 · 대상: `v2/index.html`(일반), `v2/kids/index.html`(kids)
> 기준: v0.3 (`index.html`, `kids/index.html`)에 대한 게임 기획자 관점의 냉정한 진단과 강화안

---

## 1. 냉정한 진단 — "이건 아직 게임이 아니라, 잘 만든 인터랙티브 아티클이다"

v0.3는 연출과 카피가 훌륭하지만, 게임을 게임으로 만드는 3요소(**긴장·성장·재방문 이유**)가 거의 비어 있었다. 코드 근거:

1. **긴장 부재** — stage2/4는 정답 여부와 무관하게 답만 하면 통과(`index.html:737-742`), stage1은 카드만 뒤집으면 무조건 만점(`index.html:678`). 실패가 없으니 성취도 없다. 22점 만점에서 낮은 점수가 나오기 구조적으로 어렵다.
2. **성장 부재** — 점수는 매판 22점 1회성. XP/레벨/누적/마일스톤이 전무. "어제보다 나아지는 느낌"이 출석 도장 1개에만 얹혀 있었다.
3. **리텐션 엔진이 가짜** — 이 앱의 학습 원리(간격 반복)가 곧 최고의 리텐션 훅인데, "내일/3일/1주" 예약이 localStorage에도 안 남고 알림도 없는 순수 다짐 UI(`index.html:1055-1058`)였다. 게임 진도조차 저장 안 돼 새로고침하면 intro부터.

## 2. 설계 원칙 — "좋은 중독성 = 학습과 정렬된 루프"

"느리고 깊은" 철학을 지키려면 값싼 도파민(폭죽 남발)이 아니라 **인출 노력 자체가 보상이 되는** 설계여야 한다. 모든 게임 요소는 학습 효과와 정렬될 때만 채택했다. 구현은 기존 3축(`state`/`render()`/`finishStageN()`)을 **교체하지 않고 감싸는** 방식 — 신규 로직은 순수 함수 모듈(`Store`/`SRS`/`Meta`/`Feel`)로 추가하고 기존 함수엔 1~2줄 훅만 삽입.

## 3. 게임화 4계층 (구현 완료)

### A. 리텐션 엔진 (가장 큰 ROI, 학습적으로도 가장 정직)
- **간격 반복 실제 구현**: 개념별(shelf/question/blank/detail/rebuild) 다음 복습일을 SM-2 경량 알고리즘으로 계산해 localStorage 저장(`SRS.schedule`). 홈에서 "오늘 꺼낼 N개"(`SRS.due`) 표시.
- **복습 세션(`review` 씬)**: due 개념만 짧게 백지 인출 → 성적으로 다음 복습일 갱신.
- **진도 저장/이어하기**: `go()`마다 세션 스냅샷 저장(`snapshotProgress`), 새로고침 시 홈에서 "이어서 계속" 복원.
- **데일리 롤오버**: 날짜 시드 기반 daily 상태(`seedFromDate`).

### B. 핵심 루프 게임화 (심장을 진짜 게임으로)
- **실시간 키워드 포획**: 백지에 타이핑하면 잡힌 개념 수만큼 도트/별이 실시간으로 켜짐(`updateLiveCapture`). **무엇을 잡았는지는 숨겨** "베끼기 방지" 철학 유지 — 카운터만 노출.
- **오답을 자원으로 전환**: 틀린 개념은 SRS grade<2 → 자동으로 due=내일이 되어 복습 카드화. 실패가 페널티가 아니라 리텐션 자원이 됨.
- **콤보/긴장**: 연속 정답 카운터(`state.combo`) + 콤보 피드백.

### C. 성장 메타 (매일 올 동기)
- **XP/레벨**: 완주 점수 × XP_PER + 콤보 보너스(`Meta.addXp`). 레벨 경계(`LV`)와 명칭(`LV_NAME`).
- **배지/마일스톤**: 첫 도장, 7/30일 스트릭, 5콤보, 5개 개념 숙련(`Meta.checkBadges`, `BADGE_META`).
- **개념별 숙련도**: 인출 성공 시 상승/실패 시 하락(`concept.mastery`), 결과 화면에 바로 표시.

### D. game feel 폴리시 (절제된 마감)
- **정답/인출 성공 사운드+햅틱**: 기존엔 타이머만 있던 것을 정답·콤보·레벨업·포획에 확장(`Feel`, `blip`, `haptic`).
- **결과 = 성장 리포트**: 획득 XP / 현재 단계 / 최고 콤보 / 개념별 숙련도 바 / 새 배지 / 내일 복습 예약 안내. 옛 다짐 UI를 대체.

## 4. 일반 vs kids 차별화 (코어 동일, 연출·문구·테마만 분기)

| 축 | 일반 (절제·깊이) | kids (게임적·화려) |
|---|---|---|
| 레벨 명칭 | 입문 / 견습 / 숙련 Lv.N / 달인 / 명인 | 새싹 요정 / 반짝 요정 / 기억 요정 Lv.N |
| XP 카드 | 먹색 미니멀 바 | 파랑→보라 그라데이션 + 노란 XP바 |
| 콤보 | 상단 subtle "N 연속 정답" | "콤보 N!! 🔥" 확대 팝(comboPop) |
| 사운드/햅틱 | 짧은 낮은 sine 단음 | 밝은 triangle 아르페지오 + 긴 진동 |
| 배지 | 도장형 미니 아이콘 | 큰 이모지 스티커 |
| 실시간 포획 | 회색→teal 도트 | ·→⭐ 별 |
| 성장 리포트 | 숙련도 그래프 중심 | 마스코트 🧠✨ + 별 등급 + 스티커 |
| SRS 파라미터 | 표준 간격(1·3·N일), XP_PER 6 | 짧은 간격(1·2·N일)·관대한 ease, XP_PER 8 |
| 복습 알림 문구 | "N개 개념이 오늘 복습일" | "친구 N명이 기다려요! 👋" |

코어(`Store`/`SRS`/`Meta`)는 동일 알고리즘·동일 시그니처로 두 파일에 각각 두어 유지보수 대칭성을 확보했다.

## 5. 데이터 스키마 (localStorage)

- 프로필 단일 블롭: `baekji.v1.profile`(일반) / `baekji.kids.v1.profile`(kids) — 키 스프롤·정합성 비용 제거.
- 출석 스탬프는 기존 `baekji.stamps` / `baekji.kids.stamps`를 **단일 소스로 유지**(검증된 `stampStats` 재사용, 이중 소스 방지).
- 블롭 필드: `xp` · `level` · `badges{}` · `concepts{ ease, intervalDays, due, reps, lapses, mastery }` · `progress{}`(이어하기 스냅샷) · `daily{}`.
- **날짜는 항상 인자로 주입**(`SRS.schedule(c, grade, todayK)`) → 순수 함수화로 테스트 가능.

## 6. 검증 결과 (로컬 http + 헤드리스 브라우저)

- **완주 루프**: XP 적립 → 레벨업 → 배지(firstStamp/combo5) → 5개 개념 due=내일 스케줄 ✓
- **지속성**: 완주/중단 후 새로고침 → XP·레벨·스트릭 유지, stage3 텍스트 복원, 홈에 "이어서 계속" 노출 ✓
- **SM-2**: grade3 3연속 interval 1→3→8일, ease 2.6→2.7→2.8; grade0 lapse·interval 리셋·due=내일 ✓
- **날짜 경계**: 07-31+1=08-01, 02-28+1=03-01 ✓
- **스트릭 경계**: 오늘+어제=2, 오늘 끊기면=0 ✓
- **손상 JSON**: 기본 프로필로 크래시 없이 복구 ✓
- **키 분리**: 일반/kids 프로필·스탬프 교차 오염 없음 ✓
- **콘솔 에러 0** (goatcounter localhost 경고 제외).
